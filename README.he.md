# nodebb-plugin-post-follow

מעקב אחר **פוסט בודד** במקום אחר נושא שלם, עם התראה רק כשהפוסט הזה נערך, נמחק, משוחזר או מקבל תגובה ישירה, או כשהנושא שלו מועבר, ננעל, מוצמד או משנה כותרת.

## יכולות

- **כפתור פעמון ליד כפתור התגובה** בכל פוסט (סמל בלבד). לחיצה עליו מתחילה או מפסיקה מעקב. הודעה קופצת קצרה מאשרת את השינוי, ושום דבר לא נוסף ללוח ההתראות.
- **הגדרות לכל פוסט.** חץ קטן ליד הפעמון פותח תפריט שבו בוחרים כל צירוף של: *עריכה*, *מחיקה*, *שחזור*, *תגובות ישירות* ו*שינויים בנושא* (העברה, נעילה, הצמדה, וכותרת כשהפוסט הוא הפוסט הראשון). חייב להישאר לפחות אחד מסומן, ומעקב חדש מתחיל עם עריכה בלבד.
- **מעקב מרוכז בתוך נושא.** אותו תפריט יכול לעקוב בלחיצה אחת אחרי *כל הפוסטים שלי*, *כל הפוסטים של הכותב* או *כל הפוסטים* בנושא (מגבלת המעקב עדיין חלה).
- **עמוד "הפוסטים שאני עוקב אחריהם"** בפרופיל (גלוי רק לך), עם אותו פעמון ואותן הגדרות בכל פריט. אפשר לסנן לפי קטגוריה וכותרת נושא, למיין לפי נעקבו לאחרונה, נערכו לאחרונה, תאריך הפוסט או נושא, לראות אילו פוסטים נמחקו או שהנושא שלהם נמחק או נעול, ולהשתמש ב*הפסק לעקוב אחרי הכול* וב*הפסק מעקב אחרי מחוקים / נעולים*.
- **מעקב אוטומטי**, בהגדרות החשבון: פוסטים שכתבתי, פוסטים שהגבתי להם או ציטטתי, ופוסטים ששמרתי בסימניות, עם בחירת האירועים.
- **בלי הצפת התראות.** כל עוד התראה על אותו פוסט ואותו אירוע עדיין לא נקראה, לא נשלחת למשתמש התראה חדשה.
- **סוג התראה נפרד.** בהגדרות ההתראות של כל משתמש מופיעה שורה "כאשר קורה משהו לפוסט שאני עוקב אחריו", ובה בוחרים באתר, במייל, בשניהם או בכלל לא.
- **הגבלת מעקב.** מנהלי הפורום קובעים כמה פוסטים משתמש אחד יכול לעקוב אחריהם (ברירת מחדל: 500, הערך 0 מבטל את ההגבלה) ב-*ACP ← תוספים ← מעקב אחרי פוסטים*; סימן שאלה ליד ההגדרה מסביר למה היא קיימת. אפשר לפטור קבוצות מההגבלה. מעקבים קיימים אף פעם לא נמחקים.
- **סטטיסטיקה.** ב-*ACP ← תוספים ← מעקב אחרי פוסטים* מוצגים מספר המעקבים, הפוסטים הנעקבים והמשתמשים העוקבים, הפוסטים הנעקבים ביותר וכמה התראות נשלחו (לפי סוג).
- **איפה המעקב כבוי.** מנהלים יכולים לכבות את המעקב (פעמון והתראות) בקטגוריות, בנושאים או בפוסטים מסוימים. מעקבים קיימים נשמרים.
- **ניקוי אוטומטי.** משימה יומית מוחקת מעקבים אחרי פוסטים שכבר לא קיימים, ואחרי פוסטים מחוקים (או בנושאים מחוקים) לאחר תקופת המתנה (ברירת מחדל 30 יום, 0 = לשמור). יש גם כפתור *הרץ ניקוי עכשיו*.
- **ממשק REST** (כבוי כברירת מחדל, עם סימן שאלה מסביר בהגדרות): `GET /api/v3/plugins/post-follow/posts`, וגם `GET`, `PUT`, `DELETE /api/v3/plugins/post-follow/posts/:pid`, עם אימות בטוקן API של NodeBB או בסשן. תוספים אחרים יכולים להשתמש ב-`require.main.require('nodebb-plugin-post-follow').api` (‏`follow`, `unfollow`, `isFollowing`, `getFollowedPids`) ולהאזין ל-hooks‏ `action:post-follow.follow` ו-`action:post-follow.unfollow`. הכול כפוף לאותן הרשאות, מגבלת מעקב ורשימת חסימות כמו באתר.
- **התעלמות מעריכות זעירות.** מנהלי הפורום קובעים גודל עריכה מינימלי ב-*ACP ← תוספים ← מעקב אחרי פוסטים*. עריכות ששינו פחות תווים (ברירת מחדל: 3) לא שולחות התראה לעוקבים. הערך 0 שולח התראה על כל עריכה.

העורך עצמו לא מקבל התראה, וגם לא עוקבים שאין להם עוד הרשאת קריאה לנושא. נתוני המעקב נמחקים כשפוסט נמחק לצמיתות או כשהמשתמש נמחק.

בניגוד לצפייה בנושא, לא תקבל התראות על תגובות או על פוסטים אחרים בנושא.

### יחס לצפייה בנושא

ליבת NodeBB כבר שולחת התראת עריכה (והתראת תגובה חדשה) לכל מי שצופה בנושא כולו. כדי למנוע כפילויות, התוסף מדלג על התראות *עריכה* ו*תגובה* למשתמשים ש:

- צופים בנושא **וגם**
- סוג ההתראה התואם בליבה ("כאשר פוסט נערך בנושא שאני צופה בו" / "כאשר מישהו מגיב בנושא שאני צופה בו") מופעל אצלם.

משתמש שצופה בנושא אבל כיבה את סוג ההתראה הזה, או שאינו צופה בנושא כלל, ימשיך לקבל התראות מהתוסף על פוסטים שהוא עוקב אחריהם במפורש. כך אפשר לקבל "כל התגובות בנושא, ובנוסף עריכות של פוסט אחד". התראות מחיקה ושחזור נשלחות רק על ידי התוסף, ולכן הן אף פעם לא מדולגות.

## התקנה

התוסף לא מפורסם ב-npm. מתקינים אותו ישירות מגיטהאב:

```bash
cd /path/to/nodebb
npm install github:hershaleh/nodebb-plugin-post-follow
```

לאחר מכן מפעילים אותו בלוח הניהול (הרחבות ← תוספים), בונים מחדש ומפעילים מחדש את NodeBB:

```bash
./nodebb build
./nodebb restart
```

## תאימות

נכתב עבור NodeBB 4.x (נבדק מול קוד גרסה 4.16) ועבור ערכת הנושא ברירת המחדל המבוססת Bootstrap 5 (Harmony). כפתור הפעמון נוסף לשורת הפעולות של הפוסט, ליד כפתור התגובה.

## שפות

כלולות `en-GB`, `he`, `ar`, `ru` ו-`es`. התרגומים לערבית, רוסית וספרדית נעשו במכונה, ולכן תיקונים של דוברי השפות יתקבלו בברכה: עורכים את `languages/<קוד>/post-follow.json` ופותחים Pull Request, או פותחים Issue. כדי להוסיף שפה, מעתיקים את `languages/en-GB` לתיקייה חדשה על שם קוד השפה של NodeBB ומתרגמים את הערכים (משאירים את `%1`, `%2`, `%3` ואת תגיות `<strong>`). שפות חסרות חוזרות לאנגלית.

## בדיקות

```bash
npm test
```

הפקודה מריצה שני סוגי בדיקות מהירות בעזרת מריץ הבדיקות המובנה של Node (בלי תלויות ובלי NodeBB):

- **בדיקות סטטיות** (`test/static.test.js`): תחביר של כל קבצי ה-JS, התאמה בין ה-hooks ב-`plugin.json` לקוד, קיום הקבצים, אותם מפתחות ומשתני-מיקום בכל השפות, וקיום כל מפתח תרגום שמשתמשים בו.
- **בדיקות לוגיקה** (`test/logic.test.js`): הקוד האמיתי של `library.js` רץ מול **NodeBB מדומה בזיכרון** (`test/helpers/mock-nodebb.js`: מסד נתונים, משתמשים, נושאים, פוסטים והתראות מדומים).

> **בדיקות הלוגיקה אינן מוכיחות שהתוסף עובד בתוך NodeBB.** הן בודקות רק את הלוגיקה של התוסף עצמו. כל מה שתלוי בהתנהגות אמיתית של NodeBB (תזמון hooks, שליחת התראות, תבניות, נתיבים, הרשאות וממשק הדפדפן) אינו מכוסה בהן.

### בדיקות אינטגרציה (NodeBB אמיתי)

בתיקייה `test/integration/` יש בדיקות mocha שרצות בתוך NodeBB אמיתי עם מסד Redis אמיתי: hooks אמיתיים, פוסטים ונושאים אמיתיים, התראות ונתיבי HTTP אמיתיים. מפעילים כך:

```bash
NODEBB_DIR=/path/to/nodebb npm run test:integration
```

`NODEBB_DIR` הוא תיקיית NodeBB מותקנת ומוגדרת, עם `test_database` נפרד ב-`config.json` (**הבדיקות מרוקנות אותו**), עם `"test_plugins": ["nodebb-plugin-post-follow"]` ב-`config.json`, והתוסף מותקן ב-`node_modules` שלה. המריץ בודק את כל זה ואומר מה חסר. הקובץ `.github/workflows/test.yml` מכין הכול אוטומטית בכל דחיפה.

ממשק הדפדפן (הכפתור, התפריט, חלונית ה"?" בניהול) אינו מכוסה באף בדיקה אוטומטית.
